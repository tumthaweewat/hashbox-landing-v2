n8n workflow คือ ลำดับขั้นตอนอัตโนมัติที่ต่อ node เข้าด้วยกันบนหน้าจอ — เริ่มจาก trigger หนึ่งตัว (มีฟอร์มเข้า ถึงเวลาที่ตั้งไว้ มีอีเมลใหม่) แล้วส่งข้อมูลต่อไปทีละ node จนจบงาน บทความนี้รวม 6 ตัวอย่างที่ธุรกิจไทยใช้กันจริง แต่ละตัวบอกลำดับ node ที่ใช้สร้างตามได้ จำนวน execution ต่อเดือน (ตัวกำหนดว่าต้องจ่าย n8n แผนไหน) และจุดที่มักพัง

TL;DR

  • 6 ตัวอย่าง: ฟอร์มหน้าเว็บ → LINE ทีมขาย · AI จัดหมวดอีเมลลูกค้า · รายงานสรุปทุกเช้า · งานที่ต้องรอคนอนุมัติ · ระบบติดตามอันดับ SEO ที่เราสร้างจริง · AI Agent ตอบคำถามจากเอกสาร
  • ส่ง LINE ห้ามใช้ LINE node แล้ว — LINE Notify ปิดบริการตั้งแต่ 1 เม.ย. 2025 และ n8n ประกาศเลิกใช้ node นี้ ให้ส่งผ่าน HTTP Request ไป LINE Messaging API แทน
  • workflow ที่ตั้งเวลาทุก 15 นาทีใช้ ~2,880 executions/เดือน — เกินแผน Starter ของ n8n Cloud แล้ว คิดก่อนตั้งความถี่
  • ทุก workflow ที่ใช้งานจริงควรมี Error Workflow — ไม่งั้นมันพังเงียบ และคุณจะรู้ตอนลูกค้าถามว่าทำไมไม่มีใครติดต่อกลับ

ส่วนประกอบของ n8n workflow ที่ต้องรู้ก่อนดูตัวอย่าง

1. ฟอร์มหน้าเว็บ → แจ้งทีมขายทาง LINE + บันทึกลง Google Sheets

ใช้เมื่อ: มีคนกรอกฟอร์มติดต่อบนเว็บ แล้วอยากให้ทีมขายเห็นภายในไม่กี่วินาที และมีบันทึกไว้ทุกรายการ

Executions ต่อเดือน: เท่ากับจำนวนฟอร์มที่เข้ามา — 10 รายการต่อวันคือ ~300 ต่อเดือน

จุดที่พังบ่อย:

  • ใช้ LINE node — node นี้ใช้ LINE Notify ซึ่งปิดบริการแล้ว workflow จะส่งไม่ออกโดยไม่มีอะไรผิดในฝั่งคุณ ต้องเปลี่ยนเป็น HTTP Request ไป Messaging API ของ LINE Official Account
  • ฟอร์มรอนานเพราะ workflow ทำงานก่อนตอบ — ถ้าขั้นตอนหลัง Webhook ช้า ให้ตั้ง Webhook ให้ตอบกลับทันที หรือวาง Respond to Webhook ไว้ก่อนขั้นตอนที่ช้า
  • ไม่กันสแปม — บอตกรอกฟอร์มได้ทั้งวัน แต่ละครั้งคือ 1 execution และ 1 ข้อความ LINE ที่กินโควตา

2. อีเมลลูกค้าเข้า → AI จัดหมวด → ส่งต่อคนรับผิดชอบ

ใช้เมื่อ: กล่องอีเมลรวมของบริษัทมีทั้งขอใบเสนอราคา แจ้งปัญหา สมัครงาน และสแปม ปนกัน

Executions ต่อเดือน: ประมาณตามจำนวนอีเมลที่เข้ามา — ตรวจตัวเลขจริงในหน้า Executions หลังเปิดใช้ 1 สัปดาห์ แล้วค่อยคูณเป็นรายเดือน

จุดที่พังบ่อย:

  • ไม่มีหมวด "ไม่แน่ใจ" — AI จัดผิดได้เสมอ ให้มีเส้นทางที่ส่งไปให้คนดูเมื่อโมเดลไม่มั่นใจ แทนการบังคับเข้าหมวดใดหมวดหนึ่ง
  • ลืมค่าโมเดล — ทุกอีเมลคือการเรียกโมเดลหนึ่งครั้ง ค่า AI จ่ายแยกจากค่า n8n
  • ข้อมูลส่วนบุคคล — เนื้อหาอีเมลถูกส่งไปยังผู้ให้บริการโมเดล ตรวจนโยบาย PDPA ของบริษัทก่อน

3. รายงานสรุปทุกเช้า (ยอดขาย / lead / งานค้าง)

ใช้เมื่อ: ผู้บริหารอยากเห็นตัวเลขเมื่อวานทุกเช้าโดยไม่ต้องเปิดหลายระบบ

Executions ต่อเดือน: ~30 — แผนไหนก็พอ

จุดที่พังบ่อย:

  • เขตเวลา — ตั้งเขตเวลาของ workflow เป็นเวลาไทย ไม่งั้น "เมื่อวาน" ของระบบกับของคุณคนละวัน
  • ดึงข้อมูลก่อนระบบต้นทางอัปเดตเสร็จ — บางระบบปิดยอดของเมื่อวานช้ากว่าที่คิด ตรวจเวลาที่ข้อมูลมาครบจริงก่อนตั้ง 08:00
  • รายงานไม่มาแล้วไม่มีใครรู้ — ถ้าวันไหนไม่มีข้อความ คนมักคิดว่า "วันนี้ไม่มีอะไร" ให้ workflow ส่งข้อความเสมอแม้ยอดเป็นศูนย์

4. งานที่ต้องรอคนอนุมัติก่อนไปต่อ (human-in-the-loop)

ใช้เมื่อ: มีคำขอที่ต้องมีคนกดอนุมัติ เช่น เบิกค่าใช้จ่าย ส่วนลดพิเศษ หรือโพสต์ที่ AI ร่างให้ก่อนเผยแพร่

Executions ต่อเดือน: เท่ากับจำนวนคำขอ — การรอไม่เพิ่ม execution

จุดที่พังบ่อย:

  • ไม่มีเวลาหมดอายุ — ถ้าผู้อนุมัติไม่ตอบ คำขอค้างตลอดไป ให้กำหนดเวลาสูงสุดและเส้นทางแจ้งเตือนเมื่อเลยเวลา
  • คิดว่าการรอจะกินเครื่อง — n8n เก็บสถานะของ execution ที่รอนานกว่า 65 วินาทีลงฐานข้อมูล การรอเป็นวันจึงไม่ได้ค้างอยู่ในหน่วยความจำ

งานแบบนี้คือจุดที่ n8n เหนือกว่าการเขียนสคริปต์ธรรมดาชัดที่สุด — "รอคน แล้วค่อยไปต่อ" เขียนเป็นสคริปต์ยาก แต่วาดเป็น workflow แล้วทุกคนในทีมอ่านเข้าใจ

5. ตัวอย่างจริงของเรา: ระบบติดตามอันดับ SEO (4 workflow)

นี่คือ workflow ที่ Hashbox สร้างใช้เองเพื่อติดตามอันดับคีย์เวิร์ดและ AI Overview ทุกวัน — แยกเป็น 4 workflow ที่ทำงานต่อกัน

Workflow A — ส่งงานเช็กอันดับ (ทุกวัน 06:00)

Workflow B — ดึงผลกลับมาเก็บ (ทุก 15 นาที): Schedule Trigger → Postgres (งานที่ยังค้าง) → HTTP Request (ดึงผล) → Code (เตรียมข้อมูล) → Postgres (ส่งเข้าฟังก์ชันในฐานข้อมูลที่ตีความผลต่อ)

Workflow C — แจ้งเตือนเมื่อ workflow อื่นล้ม: Error Trigger → Code (สร้างข้อความ) → HTTP Request (ส่งเข้าแชตของทีม)

Workflow D — ตรวจสุขภาพระบบทุกเช้า (09:00): Schedule Trigger → Postgres (คิวรีตรวจความผิดปกติ) → Code → HTTP Request (แจ้งทีมถ้ามีปัญหา)

สามบทเรียนจากระบบนี้:

  1. ตรรกะสำคัญไม่ได้อยู่ใน n8n — การตีความผลค้นหาอยู่ในฐานข้อมูล n8n ทำหน้าที่ขนข้อมูลอย่างเดียว ข้อดีคือทดสอบตรรกะได้ และเปลี่ยนตัวขนข้อมูลได้โดยไม่แตะตรรกะ ซึ่งเราทำจริงในภายหลัง (เหตุผลอยู่ในบทความ n8n คืออะไร)
  2. Workflow B คนเดียวใช้ ~2,880 executions ต่อเดือน เพราะรันทุก 15 นาที — เกินแผน Starter ของ n8n Cloud (2,500) ทั้งที่แต่ละรอบทำงานแค่ไม่กี่วินาที
  3. Workflow C กับ D สำคัญพอๆ กับ A กับ B — ระบบที่ไม่มีคนเฝ้า ต้องมี workflow ที่คอยบอกว่า workflow อื่นยังทำงานอยู่

6. AI Agent ตอบคำถามลูกค้าจากเอกสารของบริษัท

ใช้เมื่อ: มีคำถามซ้ำๆ ที่คำตอบอยู่ในเอกสาร เช่น เงื่อนไขบริการ วิธีใช้สินค้า นโยบายคืนเงิน

Executions ต่อเดือน: ประมาณเท่ากับจำนวนข้อความที่ลูกค้าส่ง — และทุกข้อความมีค่าโมเดล AI แยกต่างหาก

จุดที่พังบ่อย:

  • ไม่มีทางส่งต่อให้คน — Agent ที่ต้องตอบทุกคำถามจะเดาเมื่อไม่รู้ ให้กำหนดชัดว่าเรื่องไหนต้องส่งต่อ
  • ไม่ทดสอบกับคำถามจริง — ก่อนเปิดใช้ ให้รวมคำถามจริงจากลูกค้า 30–50 ข้อแล้วตรวจคำตอบทีละข้อ
  • เอกสารเก่า — Agent ตอบตามเอกสารที่ป้อน ถ้าราคาหรือเงื่อนไขเปลี่ยนแต่ไม่อัปเดตเอกสาร มันจะตอบข้อมูลเก่าอย่างมั่นใจ

สรุป: แต่ละตัวอย่างใช้ execution เท่าไหร่

ตัวเลขนี้คือสิ่งที่กำหนดว่าคุณต้องใช้ n8n แผนไหน หรือควรติดตั้งเอง — อ่านต่อที่ n8n ราคา 2026: Cloud vs Self-hosted คิดเป็นบาท

5 หลักที่ทำให้ workflow ไม่พังเงียบ

  1. มี Error Workflow เสมอ — ใช้ Error Trigger ส่งแจ้งเตือนเมื่อ workflow ไหนล้ม แล้วตั้งให้ทุก workflow ที่ใช้งานจริงชี้มาที่ตัวนี้
  2. รันซ้ำแล้วต้องไม่ทำซ้ำ — ถ้ากด retry แล้วลูกค้าได้อีเมลสองฉบับ หรือแถวใน Sheets ซ้ำ แปลว่า workflow ยังไม่พร้อมใช้งานจริง ให้มีตัวตรวจว่ารายการนี้ทำไปแล้วหรือยัง
  3. เก็บ API key ไว้ใน Credentials ของ n8n — ไม่ใส่ไว้ใน Code node หรือใน URL
  4. ตรรกะที่ต้องถูกเสมอ เก็บไว้นอก n8n — สูตรคำนวณเงิน เงื่อนไขทางธุรกิจที่ต้องทดสอบได้ ควรอยู่ในฐานข้อมูลหรือระบบที่มีเทสต์ ให้ n8n เป็นตัวขนข้อมูล
  5. export workflow เป็นไฟล์เก็บไว้ — ทุกครั้งที่แก้ใหญ่ ให้ดาวน์โหลด JSON ของ workflow เก็บไว้ในที่ที่ย้อนเวอร์ชันได้

  • n8n ราคา 2026 — คำนวณว่าตัวอย่างข้างบนต้องจ่ายแผนไหน

FAQ: คำถามที่พบบ่อยเรื่อง n8n workflow

n8n workflow คืออะไร?

คือลำดับขั้นตอนอัตโนมัติที่ต่อ node เข้าด้วยกัน เริ่มจาก trigger หนึ่งตัว เช่น มีฟอร์มเข้า ถึงเวลาที่ตั้งไว้ หรือมีอีเมลใหม่ แล้วส่งข้อมูลต่อไปทีละ node จนจบงาน การรันหนึ่งรอบเรียกว่า execution ซึ่งเป็นหน่วยที่ n8n Cloud ใช้คิดเงิน

n8n ส่งข้อความเข้า LINE ได้ไหม?

ได้ แต่ต้องส่งผ่าน HTTP Request ไปยัง LINE Messaging API ของ LINE Official Account เพราะ LINE node เดิมของ n8n ใช้ LINE Notify ซึ่งปิดบริการแล้วตั้งแต่ 1 เมษายน 2025 และ n8n ประกาศเลิกใช้ node นี้ตั้งแต่เวอร์ชัน 1.64.0

หา template ของ n8n workflow ได้ที่ไหน?

n8n มีคลัง template อย่างเป็นทางการที่ n8n.io/workflows ซึ่ง import เข้าระบบได้ทันที ก่อนใช้ให้ตรวจทุก node ว่าต้องการ credential อะไร ส่งข้อมูลไปที่ไหน และตรงกับระบบของคุณไหม template ที่ใช้ LINE node เดิมจะใช้งานไม่ได้แล้ว

ต้องเขียนโค้ดเป็นไหมถึงจะสร้าง workflow ได้?

งานส่วนใหญ่สร้างได้ด้วยการลาก node และตั้งค่าบนหน้าจอ แต่การจัดรูปข้อมูลที่ซับซ้อนหรือเรียก API ที่ไม่มี node สำเร็จรูป จะง่ายขึ้นมากถ้าเขียน JavaScript ใน Code node และอ่านเอกสาร API ได้

n8n AI Agent คืออะไร?

คือ node ที่ให้โมเดลภาษาตัดสินใจเองว่าจะใช้เครื่องมือไหนเพื่อตอบคำถามหรือทำงาน เช่น ค้นเอกสาร เรียก API หรือคำนวณ ต่างจากการเรียกโมเดลธรรมดาที่ทำตามขั้นตอนตายตัว เหมาะกับงานถาม-ตอบจากเอกสาร แต่ต้องกำหนดเรื่องที่ต้องส่งต่อให้คน และทดสอบกับคำถามจริงก่อนเปิดใช้

workflow หนึ่งนับเป็นกี่ execution?

นับหนึ่งครั้งต่อการรันหนึ่งรอบ ไม่ว่าจะมีกี่ node workflow ที่ตั้งเวลาทุก 15 นาทีจึงใช้ประมาณ 2,880 executions ต่อเดือน ส่วน workflow ที่รับฟอร์มใช้เท่ากับจำนวนฟอร์มที่เข้ามา

ทำไม workflow ไม่ทำงานตามเวลาที่ตั้ง?

ตรวจสามอย่าง: workflow ถูกเปิดใช้งานแล้ว ไม่ใช่แค่กดทดสอบ · เขตเวลาของ workflow เป็นเวลาไทย · ถ้าติดตั้งเอง เครื่องที่รัน n8n ต้องเปิดอยู่ตลอดและไม่ถูกโฮสต์ปิด process ทิ้ง ซึ่งเป็นปัญหาที่พบบ่อยบนโฮสต์แบบแชร์

จ้างทำ n8n workflow ราคาเท่าไหร่?

บริการวางระบบ n8n ของ Hashbox เริ่มต้น 29,000 บาทต่อโปรเจกต์ ไม่รวม VAT 7% คิดเป็นโปรเจกต์ไม่ใช่รายเดือน ติดตั้งบนเซิร์ฟเวอร์ของคุณเองและส่งมอบไฟล์ workflow พร้อมเอกสาร ราคาจริงขึ้นกับจำนวน workflow และจำนวนระบบที่ต้องเชื่อม
